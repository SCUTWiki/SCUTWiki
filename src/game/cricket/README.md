# 限定词斗蛐蛐

SCUTWiki 首页互动实验 001。入口：`/cricket`。

五个词，两个小人，自动打完一局。玩家只负责命名、输入五个方向性概念词和选对手；移动、出招、闪避、认输都由小人的行为策略决定。

## 编译流程

1. 词条先做归一化（NFKC、繁简、同义词、空白与标点）。
2. 太泛的词查 `BROAD_CONCEPTS` 热度锁定表，落成一个具体方向；作弊 / 控制斗兽场本身的词仍然拒绝。
3. 绝对词不再拒绝：它会生成 `absolute` 机制（不坏、不死、必中、斩杀、无限），但必定附带 `breakDuration` / `breakAmp` 破绽；带“反绝对/破无敌/无效/逆反”等词根的能力会获得可消耗的 `antiAbsolute` 次数，直接抵消一次绝对。绝对结束后没有反制的对手也能吃破绽增伤。
4. 词条会编出 1~2 个**机制**，而不是只加状态：刻印引爆、残响、反击架势、留场领域、换位、封招、牵引、蓄势、斩杀、点名、吓退、催眠、缩小、膨胀、顺手牵羊、净手、梭哈、定身、封麦、分身、镜返等。机制由确定性引擎执行，AI 输出也走同一套 schema。
5. 少数词有专属配方（如食堂=顺手牵羊+点名，早八=催眠+吓退，镜面=镜返+分身，崩山=斩杀+刻印）；其余词按词根和兵器意象组合，重/轻/赌类还会决定伤害波动。
6. 查能力库。命中则复用合约；未命中则本地确定性编译，或在配置了 AI 时交给 AI。
7. AI 输出会经过 `sanitizeAIContract` 夹回平衡区间；超时、失败、越界都会回退本地编译器。
8. 合约写入能力库。相同词条永远复用同一份合约；相近词条合并为别名。

伤害不再统一压进 20-30：轻/细/风/雨可以只有 3-15，重/山/锤/爆可以到 80-210，赌类带 84% 左右的波动；高伤害用冷却、蓄力、破绽或随机性买单。

## 新词识别

`recognition.js` 负责“没见过的词怎么读”：

- 先拆词根、意象、校园梗和英文梗，再累加元素/形态/攻击/机制权重。
- 识别结果会写进合约的 `recognition`：`kind`（recipe / semantic / lexicon / fallback / ai）、置信度、concepts、rationale 和命中的词根。
- 新词会据此决定攻击方式、形态、伤害倾向和 1~2 个机制；例如“量子火锅”=火+烹饪+机械 → 范围/留场领域/梭哈，“赛博木鱼”=机械+声音+禅意 → 光束/封麦/残响。
- 置信度低于 0.46 的词会标成“自由解释”，提示用户换更具体的词；不再静默随机。
- 卡片会显示“新词识别 / 自由解释 / 专属配方 / AI 语义识别”和置信度，悬停可看拆词理由。
- 开了 AI 时，AI 也会返回 `recognition` 元数据；AI 失败则回退本地词根识别。

AI 只做这一步，不判断胜负。战斗、积分、投降和终局判定全部由 `engine.js` 的确定性代码执行；平局逼近时按构筑新颖度触发一次“灵光”仲裁。

## 前十挑战与积分

- 前十固定为 #1 -> #10；挑战顺序必须从 #10 开始，赢下当前位才解锁下一位，输了留在原位。
- 每次挑战都会按结果结算：玩家赢加分，玩家输按双方积分差扣分；认输扣得比被击倒少。玩家赢下前十时，对手也会掉一点积分。
- 胜场预览和失败预览都显示在榜单行里；改词条会重置积分、前十进度和对手掉分记录。
- 网站预定和有趣保留不受前十顺序限制。

## 小人的“拉扯”

`createFighter` 会按招式组合推断人设（剑客、游侠、术士、守御、唤灵、游方），并影响：

- 舒适距离：游侠/术士用最远招式距离，剑客用最近招式距离，避免混搭时站错位置。
- 收招后撤：剑客/游侠/术士出手后会短暂后撤，形成进退节奏。
- 危险反应：对手蓄力近战、光束、AOE 时后撤或起跳；技能全在冷却时拉开等 CD。
- 抓破绽：对手攻击落空或被震僵后会留下 `opening`，剑客会主动压上去；自己被抓破绽时优先脱离。
- 绝对/反绝对：`absolute` 状态、`break` 破绽、`antiAbsolute` 次数会显示在 HUD 和场地状态图标里。

## 接入 AI

在游戏右上角「引擎」中填写任意 OpenAI 兼容接口：

- 接口地址：例如 `https://api.deepseek.com/v1`
- 模型名：例如 `deepseek-chat`
- API Key：只保存在浏览器 `localStorage`，不会进入仓库

未配置时使用本地语义编译器，功能完整、可离线。生产环境建议把接口调用改为服务端代理，避免在前端暴露密钥。

## 已知取舍

- 排行榜是本地榜（`localStorage`），不是共享榜；换共享存储时只需要替换 `storage.js`。
- 平衡以“每个词条约 8–18 DPS 的量级”为基线，再用对手 `power` 做难度刻度；后续可根据真实对局数据调整 `lexicon.js`、`compiler.js` 与 `roster.js`。
- 前十是固定的十个榜上模型，玩家积分会插入同一个排序；玩家行本身不可挑战。
